# 09 · MVP 开发方案

## MVP 定义（垂直切片）

**目标**：2 周内做出"第一章完整可玩 + 在 iPad 真机上跑"，验证全部技术与体验假设。

**包含**：
- 引擎四件套：RoomScene（数据驱动）、UIScene（物品栏/字幕）、GameState/存档、谜题基类
- 第一章 4 个谜题（1-1 转盘锁 / 1-2 排序 / 1-3 索引 / 1-4 VHS调谐）——恰好覆盖 4 种交互范式
- 5 个镜头（S01×2、S02×2、S03×1），**灰盒美术**（色块+文字标注，不等插画）
- 1 个 PostFX（颗粒）、3 个音效（点击/获得/解谜成功）、1 段环境底噪
- Capacitor 打包 → 自己的 iPad 真机运行

**刻意不包含**：正式美术、音乐、第2–6章、隐藏结局、双屏联动（5-3 是技术最重单体，放第二里程碑单独攻坚）。

## MVP 验收清单

- [ ] iPad 真机 60fps，触控热区无误触
- [ ] 从启动到看完第一章结尾钩子 ≤ 15 分钟
- [ ] 杀进程重开，进度精确恢复
- [ ] 一个不看攻略的朋友能独立通关第一章（卡关处记录下来调整提示）
- [ ] 新增一个房间只需 JSON+背景图（用第2章第一个房间验证）

## 里程碑路线（总计 8 周，单人）

| 里程碑 | 周 | 内容 | 退出标准 |
|---|---|---|---|
| M0 引擎+MVP | 1–2 | 上述垂直切片 | MVP 验收清单全过 |
| M1 内容管线 | 3–4 | 第2、3章灰盒（含无限图书馆循环、双时代对位）；可复用谜题组件库成型 | 1–3章连续可玩 |
| M2 技术攻坚 | 5 | 5-3双屏联动、镜像档案室、Win98子场景、VHS/glitch shader | 4–5章灰盒可玩 |
| M3 内容收口 | 6 | 第6章+双结局+隐藏收集链；全流程灰盒通 | 全流程90–120min确认 |
| M4 美术替换 | 6–7 | 28张背景+角色+物品图标分批替换灰盒（边画边换，JSON不动） | 视觉完成度80% |
| M5 音频+打磨 | 7–8 | 音乐音效、提示系统调参、文案校对、性能 | 内容锁定 |
| M6 发布 | 8 | Capacitor 签名、图标/启动屏、TestFlight 内部组 | 朋友们装上了 |

## 风险与对策

| 风险 | 对策 |
|---|---|
| 美术量超支（最可能） | 灰盒先行让美术与逻辑完全解耦；万一画不完，砍 S14 镜像房间一镜、S17 一镜（剧情可调整），背景从 28→24 |
| 5-3 双屏联动复杂度 | 已隔离为独立里程碑；保底方案：退化为"两个房间交替切换+还书箱"（同叙事，半技术量） |
| 流程不足 90 分钟 | 不加谜题；增加档案阅读文本与 vignette（叙事密度而非谜题数量） |
| Win98 中文像素字体版权 | 用开源 Fusion Pixel（OFL 协议） |
| 真实校园敏感性 | 片头声明"基于真实校园的虚构故事"；不出现真实人名；建筑名保留（非商业、致敬向） |

## 砍单优先级（如果只剩一半时间）

保：第1/2/5/6章 + 真结局（主线闭环完整）。
砍：第3章并入第2章（时间胶囊保留、循环走廊砍）、第4章狐狸戏并入第5章、隐藏结局改为通关后一张图。
**主题表达不降级，体量降级。**
